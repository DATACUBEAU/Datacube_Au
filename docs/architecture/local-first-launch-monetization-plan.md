# DataCube AU — zero-budget launch decision
Date: 2026-11-25. This decision supersedes earlier plans to activate cloud AI at launch.

## Scope
- Kotlin/Jetpack Compose is the active Android client; Room, WorkManager and local models remain the inference/document backbone.
- Local inference, RAG, study tools, voice, podcasts, document storage and previously authenticated offline access remain on-device.
- Cloud AI/OpenRouter, cloud credit wallets and credit purchases are deferred: UI status **Coming soon**. No provider call, automatic cloud fallback, cloud reservation, credit purchase or paid hosting for this launch. Preserve existing code for a separately reviewed future release. Do not delete historical billing records or invalidate existing subscriptions.
- Keep Supabase as the lightweight control plane for authentication, profiles, existing billing/admin and future server-authoritative rewards; Vercel for official download/sign-in and GitHub Actions/Releases for build/update distribution. Do not introduce paid infrastructure without an explicit budget and approval.

## Execution gates
1. Stabilize: offline cold start, RAG citations, native stop/stream controls, independent background jobs, model backup and restore, voice/podcast continuity, low-RAM and thermal performance. Physical device acceptance and signed APK verification remain mandatory.
2. Distribute: official website first, preserve package/signing identity and increasing version code; separate future store distribution channels. Existing GitHub release manifest and Android updater remain the current delivery path; a Supabase release manifest is a future design, not a launch prerequisite. Current personally signed test APK is not a store-ready production release.
3. Ads: design a centralized provider-neutral Ad Engine, with proposed websiteRelease/Start.io and supported-store flavor/AdMob. No ad SDK or provider account is activated in this change. Confirm provider approval, eligible publisher/account holder, genuine verification, age-appropriate consent and applicable platform rules before implementation. No ads on offline startup, authentication, document reading, generation or voice playback; no document/chat content sent for ad targeting. Network/provider failure must not block basic local features.
4. Rewards: optional, configurable server-authoritative grants with provider-specific verification, replay/idempotency protection, no rewards for clicks or artificial impressions. Proposed rolling five-hour access begins when a verified entitlement is granted; candidate rewards include voice minutes, study generation and SmartNote Interactive. Three-task concept and reward amounts require provider-policy review and product validation. Offline entitlements must be verifiable, scoped and fail safely; basic local features stay available.
5. Pro: proposed weekly/monthly ad-free eligible local premium features; price and payment/store policy to be decided. Preserve existing account and subscription management. Do not sell cloud access or credits while cloud is paused. Existing billing compatibility is not proof of native entitlement enforcement.
6. Cloud: only reopen after revenue/budget approval, security review, user consent for remote processing, server-side provider keys, bounded per-user and global spend, idempotent reservation/reconciliation, streaming/cancellation, and explicit operational kill switch. No cloud costs are authorized by this plan.

## Launch blockers
Physical-device validation, durable production signing, distribution/provider approvals and age/account eligibility, reward verification, native billing integration and local account isolation. Revenue projections are hypothetical, not launch forecasts. Start.io/AdMob availability and applicable marketplace/payment terms must be verified before shipping monetization. No changes to Supabase schema, provider credentials, billing or deployed infrastructure are needed for the Coming soon label.
