# Mobile sign-in: exchange transport investigation (2026-11-26)

## Existing contract
Android creates a short-lived device authorization with a challenge. The canonical website starts Google OAuth using Supabase PKCE. The callback exchanges the authorization code exactly once and restores the browser session. The signed-in browser explicitly approves the pairing code; the existing device proof allows Android to consume the approval. No database migration, new session protocol, or APK change is required.

## Evidence
- Recent live Google authorization and callback requests returned HTTP 302; the subsequent PKCE token POST was not observed in the inspected window.
- Production mobile authorization create/cancel smoke passed (HTTP 201/200), GitHub Actions run 45905525989.
- Live OPTIONS requests from the canonical origin passed for standard SDK headers, x-device-id, and the extra platform/runtime headers generated by SDK 2.93.1, run 45905650137. This rules out the tested CORS preflight, not every possible client network failure.
- The lockfile pins Supabase JS 2.93.1. Its navigator lock implementation aborts on a pending acquisition timeout without recovering an orphaned lock. Version 2.98.0 contains upstream fixes #2106 and #2125 (five-second lock acquisition and orphan recovery). The user's exact failing browser lock state has not been captured; this is an evidence-based correction to a known vulnerability in the existing path, not proof of the incident's sole root cause.

## Changes
Pin the existing SDK to 2.98.0 using registry-verified metadata; preserve SDK cross-tab session coordination. Do not attach device metadata to authentication requests. Bound the single-use PKCE token transport to 12 seconds and do not replay it in the application fetch wrapper. Distinguish safe diagnostic categories in the existing callback. Add a browser regression for an abandoned cross-tab authentication lock; retain the existing PKCE challenge/verifier test and approval tests.

## Release gate
Require frozen-lockfile installation, typecheck, the existing mobile authorization and auth guard browser tests, and a production build. Confirm the real Android-to-Google flow after deployment. Do not claim live OAuth completion from the mocked tests.
